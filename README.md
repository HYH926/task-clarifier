# Task Clarifier

Task Clarifier 是一个用于开发或执行任务之前的通用任务理解、需求澄清与规划 Skill。

它不负责完成原任务，而是帮助用户先想清楚：任务是什么、为什么做、依赖什么、边界在哪里、怎样验收，以及应该采用什么方案。

作者：HYH926

## 核心原则

- 只做任务开始前的理解与规划，不执行原任务。
- 通过四个阶段逐步确认，不自动进入下一阶段。
- 对话轮数由任务复杂度和信息完备程度决定，不设固定总轮数。
- 未确认的关键事实不会被 AI 擅自补全。
- 提示词只是规划确认后的可选辅助，不是核心交付物。
- 支持只读读取用户主动提供的主会话交接摘要；平台不支持时明确降级。

## 三种运行模式

读取任务后会先判断模式，并向用户说明理由、等待确认：

- **任务模式**：单一交付物、低风险、可逆、验收清楚，输出规划报告，不生成 PRD。
- **功能模式**：单个客户端或模块、少量角色、无支付/退款/复杂权限，输出轻量 PRD 和规划报告。
- **项目模式**：多端、多模块、多角色权限、交易支付、安全合规、外部集成或多里程碑，输出完整 PRD。

多端项目默认**每个端分别生成一份 PRD**，例如用户端、商家端、平台后台；共享的平台决策先确认，再写入各端。用户明确要求时才生成一份总 PRD。

项目模式不会一判定就生成 PRD。只有业务目标、用户角色、范围、关键流程和技术约束已确认，且用户确认 PRD 目录后，才进入 PRD 生成。

## 四个阶段

1. 理解确认：说明任务本质、背景、关键概念、依赖、难点、风险和未知，帮助用户理解任务。
2. 需求与边界确认：确认目标、交付物、受众、范围、非目标、约束和验收；功能/项目模式补充角色、流程、技术约束和关键决策。
3. 方案规划确认：任务模式形成规划报告；功能模式生成轻量 PRD；项目模式完成技术选型讨论并分别生成各端 PRD。
4. 可选提示词：仅在用户明确确认规划/PRD 后，按需生成可移交给其他执行会话的自包含提示词。

每个阶段都会停下来等待用户确认或修改；用户确认前不会进入下一阶段。

## 安装

将仓库目录放入任意支持 SKILL.md 的技能目录。

ZCode 用户目录：~/.zcode/skills/task-clarifier/

或跨工具目录：~/.agents/skills/task-clarifier/

Codex 用户目录：~/.codex/skills/task-clarifier/

Claude Code 用户目录：~/.claude/skills/task-clarifier/

其他支持 Agent Skills 的工具可使用其对应的技能目录。技能不需要额外依赖。

## 使用

手动调用，例如：

使用 task-clarifier，帮我理清这个任务，不要执行：[描述你的任务]

宿主支持斜杠技能时也可以使用 /task-clarifier。

## 适用场景

- 学校作业、课程展示、报告和研究任务
- 日常小任务和计划安排
- 决策与分析
- 编程和项目准备

## 边界

- 不撰写可直接提交的作业正文、通知、论文结论或代码。
- 不创建或修改原任务交付物。
- 用户说“开始吧”“继续”不会授权执行原任务。
- 只读取用户主动提供的资料或经授权的主会话。
- 降级、读取失败和上下文时效风险会明确告知，不静默假装成功。
